# M6: Everyday workflows (menu)

**Start:** `scripts/lab-start.sh m6`

You have about **25 minutes**. Work in your trio. Use **Manual** mode so you see each edit and command.

**Pick one workflow.** If you finish, pick another. Try not to all pick the same one.

**Before you start, write down what your evidence will be.** At the end you show it, rather than saying it works.

**Checkpoint at about minute 10:** you have chosen a workflow, named your evidence, and (where it applies) written a failing or characterization test.

## Hints that apply to every workflow

- **Reproduce before you fix.** Show the failing test first.
- **A refactor keeps every result. A fix changes behavior.** If you find a bug while refactoring, write it down and keep the changes apart.
- **Read the test diff separately** (`git diff -- test/`).
- **If your docs and the code disagree, work out which one is right** before you change either. Check the requirements.
- **Use history.** `git log -S`, `git blame`, and `git bisect` with a failing test can find where a behavior changed.
- **Generated text is a set of claims.** Check each one.

## In your trio
- **Driver** prompts. **Reviewer** reads each edit and command. **Observer** notes the evidence and anything the agent assumed.
- Status: 🟢 done, 🟡 slow, 🔴 blocked.

## Success looks like
Your workflow ends with evidence you can **show on screen**, the diff is in scope, and you can say what the agent assumed or got wrong, if anything.

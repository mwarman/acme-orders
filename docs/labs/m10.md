# M10: Capstone

Choose a track. About **40 minutes** including the retrospective.

## Track A: your own repository
Use a repository you are **permitted** to use with Claude Code (personal, open source, or approved by your organization). You decide; no one will ask to see client code. If you are not sure it is allowed, use Track B.

1. Pick **one small task**. If setup is taking more than five minutes, switch to Track B.
2. Run **explore, plan, implement, verify**. Name your **evidence** before you start.
3. Write or update a `CLAUDE.md` for the repository.

## Track B: extend acme-orders
**Start:** `scripts/lab-start.sh m10-b`. The request is in `docs/issues/ISSUE-201.md`:

> *"Let customers choose store credit instead of a card refund. Give them a 10% bonus as a thank-you."*

That is the whole request so far. The product owner (your instructor) can answer questions.

**Scope for this lab:** the credit ledger, the bonus math, and a **read-only balance endpoint**. Spending credit is out of scope.

If your change needs new database tables or columns, `npm run db:reset` recreates the local database from the schema.

**Ask about whatever is unclear before you build.** Then plan, build with tests first, and verify.

## Your evidence
Before you start, write down what you will show at the end: the tests, the commands, and anything you could not check.

## Retrospective (both tracks, about 7 minutes)
In your trio, answer:

1. **One thing the agent did well.**
2. **One failure, and its category:** runaway scope, an invented API, test-gaming, a silent assumption, stale knowledge, or context rot.
3. **One change you will make to how you work next week.** Make it small enough that you will actually do it.

## Take-aways
Everything you need to keep is in [`docs/takeaways/`](../takeaways/README.md), including an **adoption playbook template** for taking this back to your team.

# M5: Verification loops

**Start:** `scripts/lab-start.sh m5`

`npm run test` now shows **two failing tests**. That is on purpose.

Use **Manual** mode so you see every edit and command.

## Task A: red tests (7 minutes)

1. Tell Claude Code, in these exact words: **"Make the failing tests pass."** Do not add detail. You want to see what it does with a bare goal.
2. **Before you accept anything**, look at what changed:

   ```bash
   git diff --stat
   git diff -- test/
   ```

3. For **each** of the two failing tests, fill in a verdict:

   | Test | Code wrong or test wrong? | Your evidence | What did the agent do? | Accept? |
   |---|---|---|---|---|
   | | | | | |

   Your evidence should point to something written down: a requirement ID in [`docs/product-requirements.md`](../product-requirements.md), a lifecycle diagram, another test. "It seemed wrong" is not evidence.

4. When you are satisfied, run `npm run test`, `npm run lint` and `npm run typecheck`, and show the output.

## Task B: review someone else's diff (7 minutes)

```bash
git show lab/m5-review
```

A colleague added a refund export for finance. Write review comments as you would on a pull request. Give each a severity:

- **Blocker**: must be fixed before this ships
- **Major**: should be fixed
- **Minor**: worth mentioning

For **each** comment, also write: **would the existing tests catch this?**

Look at the checklist below. Remember that a diff only shows what changed, not what is missing. Open the file if you need to.

## Diff review checklist

1. `git diff --stat`: is the size what I expected?
2. **Test files on their own**: deleted, skipped, weakened, or edited to fit?
3. **Scope**: anything I did not ask for?
4. **Risky edges**: authorization, validation, errors, data access, secrets, logging.
5. **Context**: what do the neighbouring files do that this does not?
6. **Evidence**: did I see passing test, lint and typecheck output?

## In your trio
- **Driver** prompts. **Reviewer** reads the diff. **Observer** keeps the verdict table.
- Status: 🟢 done, 🟡 slow, 🔴 blocked.
- **Checkpoint:** by about minute 7, both verdicts are written down.

## Success looks like
- A verdict **and evidence** for both tests.
- No test weakened, skipped or deleted without a reason you can point to in the requirements.
- `npm run test` fully green, plus lint and typecheck, with the output in front of you.
- A review with at least two comments, and for each, whether a test would catch it.

## Stretch
Turn your most serious review comment into a **failing test**, then make it pass. That is the red-then-green loop applied to a code review.

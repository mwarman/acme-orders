# M9: Scaling out

**Start:** `scripts/lab-start.sh m9` · Use **Manual** mode.

Running more than one session at a time is easy. **Reviewing and merging what they produce is the hard part.**

## Task (about 12 minutes)

Two sessions, in parallel, in **separate git worktrees**, so they cannot touch each other's files.

- **Session A: operations report a problem.** *Reserved stock keeps climbing for products customers say they could not buy.* Find and fix it, with a regression test.
- **Session B: `src/notifications/` has no tests.** Write tests in the project's style. If a test fails, decide whether the **code** or the **test** is wrong, and fix the right one.

In a trio: one person drives each session, and the third reviews both diffs.

### Set up
Start each session in its own terminal:

```bash
claude --worktree fix-stock
claude --worktree tests-notify
```

Each creates a checkout under `.claude/worktrees/<name>/` on a new branch `worktree-<name>`. A worktree is a **fresh checkout**, so install and set up **in each one**:

```bash
npm ci
npm run db:reset
```

> New worktrees branch from the repository's **default branch on the remote**, not from commits you made locally. That is fine here, because the lab starts from the same code.
> Do **not** add a `.worktreeinclude` file for this lab. It copies ignored files such as `.env` into every worktree.

### Merge and verify
When both are done, **review each diff first** (`git diff --stat`, then the test files on their own), then back in your main checkout on `work/m9`:

```bash
git merge worktree-fix-stock
git merge worktree-tests-notify
npm run test && npm run lint && npm run typecheck
```

Clean up:

```bash
git worktree list
git worktree remove .claude/worktrees/fix-stock
git worktree remove .claude/worktrees/tests-notify
```

## Questions for your trio
- What did running in parallel **save**? What did it **cost** (your attention, review time, setup)?
- Where did the two sessions **not** conflict, and why?
- What would have happened if both had changed the same function?

## Stretch: make a conflict on purpose
Start a **third** session in a worktree and have it add a small change in the **same function** that session A fixed (for example, record declined payments in the outbox). Merge it. Resolve the conflict, and say what you checked before you trusted the result.

## Try it: a headless run (read-only)
Claude Code can run **without a person at the keyboard**. This one only reads and summarizes:

```bash
npm run test 2>&1 | claude -p "Summarize any failing tests in at most 5 bullets. Do not change anything." \
  --permission-mode dontAsk --allowedTools "Read,Grep,Glob" --output-format json
```

Read the output. Note the fields about cost. Then answer: **what is the permission set for this run, and who approved it?** Check `claude --help` for the flags available on your version.

## Success looks like
- Both sessions finished in their own worktrees and merged cleanly.
- The merged tree is green, and you reviewed **each** diff before merging.
- You can name **two costs** of parallel work and **one control** on an unattended run.

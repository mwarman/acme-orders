# M3: Prompting for agents

**Start:** `scripts/lab-start.sh m3`

## The ticket
Support has asked: *"Refunds for items bought with a promo code need to be correct."*

Your instructor is the **product owner**. Ask them questions in the PO channel. They will answer as the business would, and only what you ask.

## Setup
- Use **plan mode** to explore and plan (Shift+Tab until the status bar shows it, or `claude --permission-mode plan`).
- Switch to **Manual** mode to implement, so you see each edit and command. Confirm the mode in the status bar.

## Task (15 minutes)
1. Write a prompt with **intent, constraints, acceptance criteria and process** (skeleton below). Run it in plan mode.
2. **Read the plan** before approving it. Ask the PO about anything unclear.
3. Approve, then implement with the **test first**. Run `npm run test`, `npm run lint` and `npm run typecheck`, and show the output.
4. Check your diff. Is it only what the ticket needs?

## Prompt skeleton
```text
Goal:        what you want and why; point to the source of truth
Context:     where to look (files, docs), tests that show the style
Constraints: what must not change; patterns to follow; what is out of scope
Acceptance:  how we will know: a failing test first, commands to run, output to show
Process:     explore first; ask me about anything ambiguous; give me a plan; wait for approval
```

## In your trio
- **Driver** prompts. **Reviewer** reads the plan and the diff. **Observer** logs every **assumption** the plan makes, and counts how many times your group **repeats the same instruction**.
- Status: 🟢 done, 🟡 slow, 🔴 blocked.
- **Checkpoint:** by about the sixth minute, everyone has a plan they have **read**.

## Success looks like
- Your prompt has all four parts.
- You can name one assumption the plan made that nobody gave it, and what you did about it.
- A test failed before the change and passes after. Test, lint and typecheck pass, and you can show the output.
- Your diff is limited to what the ticket asks.

## Stretch
Without changing code, produce a plan for removing floating-point arithmetic from the legacy pricing module with no change in behavior.

## If you correct the agent twice on the same thing
Stop. Run `/clear` and write a better first prompt that includes what you learned.
